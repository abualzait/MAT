### التحديث v1.46.0 (نظام الشكاوى الأمنية الذكية: المسح الضوئي بالذكاء الاصطناعي، سير عمل الحاكم الإداري، ومطابقة المراكز الأمنية)

   - لوحة متكاملة تدعم **السكانر / السحب والإفلات / اللصق المباشر (`Ctrl+V`) / التقاط الكاميرا** لرفع وثائق الشكاوى الورقية بصيغ (`JPG`, `PNG`, `WEBP`, `PDF`) بحد أقصى `10MB` مع التحقق من التوقيع الثنائي للملفات (Magic Bytes) وحفظها بأسماء UUID معزولة داخل `data/complaint_scans/` دون إمكانية الوصول المباشر غير المصرح به.
   - دعم تعدد الشاكين والمشتكى عليهم مع تصنيف نوع الطرف (`مواطن`, `مؤسسة تجارية`, `مؤسسة حكومية`, `منشأة`) وحقول التحقق الرسمية (`توقيع المشتكي`, `الإقرار بعدم وجود قضية منظورة أمام المحاكم`, `تاريخ الشكوى الورقي`).
2. **محرك القراءة والتحليل القانوني والإداري بالذكاء الاصطناعي (`mat_llm_engine.py`):**
   - استخراج تلقائي لبيانات استمارة الشكوى وتحليل الوقائع والتوصية بالإجراء الأنسب (`توديع عن طريق مركز أمني`، `اتصال هاتفي`، `توديع مغفور`، `حفظ / توجيه للقضاء المختص`) مع نسبة الثقة (`ai_confidence`).
   - دعم متعدد المزودين: **Google Gemini** (`gemini-2.5-flash`)، **OpenAI** أو أي خادم متوافق (`gpt-4o`)، و**Ollama** المحلي (`llama3.2-vision`)، مع شاشة إعدادات خاصة برئيس القسم (`#modalLlmSettings`) تشمل اختبار الاتصال المباشر وإخفاء المفاتيح السرية، والانتقال السلس للوضع اليدوي (`manual_fallback`) عند عدم توفر مفتاح أو انقطاع الاتصال.
3. **مسار العمل الإداري رباعي المراحل (`نظر الضابط` -> `تنسيب رئيس القسم` -> `قرار الحاكم الإداري` -> `التنفيذ`):**
   - **نظر الضابط (`officer` / `admin`):** تسجيل الإجراء المقترح والملاحظات الإلزامية قبل الاعتماد أو تحديث حالة التنفيذ (`in_execution` / `completed`) بعد القرار، مع إمكانية الرفع المباشر لرئيس القسم.
   - **تنسيب رئيس القسم (`admin`):** إضافة مشروحات القسم وتثبيت الإجراء المنسب والمركز الأمني المختص ورفع المعاملة للحاكم الإداري (`pending_governor`).
   - **حساب وبوابة الحاكم الإداري (`governor` — `عطوفة المتصرف`):** الدخول المباشر تلقائياً إلى طابور اعتمادات الشكاوى الأمنية مع بطاقة قرار إلكتروني حصرية (`موافقة`، `تغيير_الإجراء`، `رفض`) وإعادة التوجيه عند الرفض.
4. **المطابقة الجغرافية التلقائية للمركز الأمني (GIS Nearest Police Station Matcher):**
   - تحليل وتطبيع عنوان المشتكى عليه ومطابقته مع قاعدة البيانات الجغرافية `data/amman_areas.json` لتحديد **أقرب مركز أمني** و**مديرية الشرطة** و**اللواء** والإحداثيات، مع زر فتح مباشر داخل دليل المراكز الأمنية على الخريطة.
5. **التكامل التلقائي مع أدوات MAT (المواعيد وحجز الملفات) والإشعارات الفورية:**
   - عند اعتماد **`اتصال هاتفي`**: يُنشأ تلقائياً موعد في `mat_simple_appointments`، وتظهر الشكوى لضابط الاتصال (`caller`)، ويُرسل إشعار FCM فوري.
   - عند اعتماد **`توديع عن طريق مركز أمني`** أو **`توديع مغفور`**: يُحجز رقم الشكوى تلقائياً في أداة تتبع الملفات (`mat_reserved_files` و `mat_file_custody_log`)، ومع `توديع مغفور` ترتفع الأولوية تلقائياً إلى **`عاجل`**.
   - إشعارات دفع فورية (FCM) في الخلفية عند الانتقال إلى `pending_section_head`، `pending_governor`، وصدور قرار الحاكم الإداري.
6. **متابعة قاعدة 90 يوماً — كف الطلب (`90-Day Stop Rule`):**
   - احتساب تلقائي للأيام المنقضية منذ `last_followup_at` مع مستويات تحذير (`normal` < 75 يوم، `warning` 75–89 يوم، `expired` >= 90 يوم)، وزر تسجيل متابعة الشاكي لإعادة تصفير العداد، وزر تفعيل `كف طلب (90 يوماً)` (`stopped_90_days`).
7. **التصدير الرسمي بصيغة Word (`.docx`) والطباعة الرسمية:**
   - تعبئة النموذج الرسمي `complaint_form_editable.docx` برمجياً عبر مكتبات بايثون القياسية (`zipfile` + `xml.etree.ElementTree`) بالبيانات والأطراف ومشروحات القسم وقرار الحاكم الإداري، إلى جانب كشف طباعة عربي متجاوب متعدد الصفحات.
